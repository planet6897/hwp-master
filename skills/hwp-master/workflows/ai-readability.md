# AI 가독성 진단

기존 HWP/HWPX 가 AI 가 읽기 쉬운 구조인지 점검하고, 고치는 법을 알려 준다. 읽기만 하고 원본은 고치지 않는다.

근거는 두 가지다.
- 행안부 'AI 시대 행정문서 작성 가이드라인': 서술형 문장으로 쓰고, 표 안의 표와 복잡한 셀 병합을 피한다.
- 지디넷 2026-11-10 기사: 투명 표·표 안의 표·의전용 편집 때문에 AI 가 데이터와 틀을 구분하기 어렵다.

이런 요청이 이 라우트다.

- "이 보고서가 AI 가 읽기 좋은 구조인지 봐 줘", "AI 가이드라인에 맞는지 점검해 줘"
- "왜 AI 요약이 엉뚱하게 나와?" (문서 구조 원인 찾기)

## 실행

```bash
python3 scripts/ai_readability.py <프로젝트> sources/<문서> [...] [--min-score 80]
```

결과 파일은 `validation/ai_readability_<시각>.json` 이다. 문서마다 다음이 들어 있다.
- `score`(100점)·`grade`(A ≥ 90, B ≥ 80, C ≥ 65, D)
- `checks`: 항목마다 `code`·`count`·`penalty`·`blockIds`·`fix`

`blockIds` 는 Extract 의 `document.json` 블록 ID 다. 같은 문서로 Extract 를 돌리면 그 위치의 글을 바로 찾을 수 있다.

| 코드 | 항목 | 감점 | 고치는 법 |
|---|---|---|---|
| A01 | 표 안의 표 | -5/개 (최대 -20) | 안쪽 표를 바깥 표 밖으로 꺼낸다 |
| A02 | 복잡한 병합(병합 칸 30% 이상·머리 3단 이상) | -3/표 (최대 -15) | 머리 행을 1~2단으로, 칸마다 값 하나 |
| A03 | 레이아웃 표(제목 상자·투명 표·한 행 표) | -1/개 (최대 -15) | 문단 스타일(개요 제목·본문)을 쓴다 |
| A04 | 공백·탭 정렬 | -1/개 (최대 -10) | 표나 탭 설정을 쓴다 |
| A05 | 빈 문단 간격(2개 이상 연속) | -1/곳 (최대 -10) | 문단 위·아래 간격을 쓴다 |
| A06 | 손 번호("1." "가." 를 글자로) | -0.2/개 (최대 -10) | 한글 자동 번호를 쓴다 — Beautify 라우트가 바꿔 준다 |
| A07 | 그림만 있는 쪽 | -5/쪽 (최대 -10) | 그림 속 글을 본문으로, 또는 설명 문장 |
| A08 | 단편만 있는 장(개조식 3개 이상 모두 서술어 없음) | -2/장 (최대 -10) | 장마다 핵심을 서술형 문장으로 한 번 쓴다 |

## 개선본 만들기

"AI 가 읽기 좋게 고쳐 줘"라고 하면 원본은 두고 AI 가독성 개선본을 새로 만든다.

```bash
python3 scripts/ai_restructure.py <프로젝트> sources/<문서> [...] [--preview]
```

문서 모델(`document.json`)을 HDS 로 다시 짜서 Quick 빌드로 `exports/ai/<문서>.hwpx`(명세는 `.hds.json`)를 만든다.

| 항목 | 개선본에서 |
|---|---|
| A03 레이아웃 표·글상자 | 칸·상자 글을 일반 문단으로 푼다 |
| A01 표 안의 표 | 안쪽 표를 바깥 표 바로 뒤로 꺼낸다(바깥 칸에 `[아래 표 n]`). 안쪽 상자 표는 문단으로 |
| A02 복잡한 병합 | 병합을 풀고 덮던 칸마다 같은 글을 둔다(칸마다 값 하나) |
| A04 공백 정렬 | 글 가운데 공백·탭 여러 개를 하나로 |
| A05 빈 문단 | 옮기지 않는다 |
| A06 손 번호 | 짧은 `1.`·`가.`·`Ⅰ.` 항목은 개요 제목(자동 번호), 개조식은 단계 목록 |
| ※·* 주석 | 앞 문단·항목의 각주 |

보고서는 `validation/ai_restructure_<시각>.json` 이다. 다음 항목이 들어 있다.
- 원본과 개선본의 점수·등급·항목(`before`·`after`)
- 원본 글 단위가 모두 옮겨졌는지(`coverage`, 항목 기호·공백은 빼고 비교)

보고서의 판정 코드는 다음과 같다.
- **오류**: 글이 하나라도 빠지면 I103, 빌드가 실패하면 I102. 그 문서는 완료로 보고하지 않는다.
- **경고**: 그림은 옮기지 않는다(I201). 개선본 점수가 원본보다 낮으면 I202.

개선본은 AI·검색·요약용 정리본이다. 그림과 머리말, 글자 모양은 빠진다. 제출용 원본을 대신하지 않는다고 알린다.

## 답하기

1. 점수·등급과 감점이 큰 항목 3개를 위치(쪽·블록)와 함께 알린다.
2. 고치기를 원하면 이렇게 안내한다.
   - 손 번호(A06)는 Beautify 라우트로 자동 번호로 바꾼다.
   - 나머지는 한컴에서 고치거나, 이 프로젝트로 새로 만든다(Default·Convert-in).
3. 새로 만드는 문서(Default·Quick·Convert-in)는 빌드 검사에서 같은 진단을 한다. 80점 미만이면 경고 R108 을 낸다.
