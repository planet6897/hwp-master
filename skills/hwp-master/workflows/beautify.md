# 기존 문서 번호 정리 (Beautify)

손으로 친 항목 번호("1. ", "가. ", "1) " …)를 한글의 개요 번호로 바꾼다. 글자는 그대로 두고
문서 구조만 고친다. 바꾼 뒤에는 개요 보기·차례 만들기·번호 자동 갱신이 동작한다.

**쪽 구성은 보장하지 않는다.** 한글은 개요 번호 뒤를 번호 정의의 간격으로 띄우고, 넘친 줄을 본문
시작 위치에 맞춰 들여 쓴다. 손으로 친 공백과 폭이 달라서 꽉 찬 제목 줄이 두 줄이 되고 뒤 내용이
다음 쪽으로 밀릴 수 있다. 실제로 한 보도자료(8쪽)를 바꾼 뒤 한컴 2024 PDF가 9쪽이 됐다. rhwp 는 이
경계를 한글과 똑같이 재현하지 못해 판정에서 놓칠 수 있으므로, 적용 뒤에는 항상 B150 경고를 내고
한글에서 열어 확인하게 한다.

## 절차

```bash
python3 scripts/project_manager.py import-sources <프로젝트> <문서.hwpx>
# HWP 는 먼저 HWPX 로: rhwp export-hwpx sources/<문서>.hwp sources/<문서>.hwpx
python3 scripts/beautify.py propose <프로젝트> sources/<문서>.hwpx      # → history/beautify_<시각>.plan.json
#   계획의 items 를 읽고, 바꾸지 않을 문단은 지운다 (preview 로 확인)
python3 scripts/beautify.py apply <프로젝트> history/beautify_<시각>.plan.json
```

산출: `exports/<이름>_beautify_<시각>.hwpx`, `validation/beautify_<시각>.json`.

## 무엇을 바꾸나

- 대상은 구역 본문 문단이다. 표·글상자 안 문단, 개체(표·그림 등)를 품은 문단, 차례 항목은 그대로 둔다.
- 공문서 항목 순서(1. → 가. → 1) → 가) → (1) → (가) → ①)만 다룬다. 개조식 기호(□ ○ - ㆍ)는 글머리표라 대상이 아니다.
- 문서의 개요 번호 정의가 이 순서여야 한다. 한컴 새 문서의 기본값이 이 순서다.
  rhwp `scaffold`로 만든 문서처럼 번호 정의가 없으면 B001 로 멈춘다(자동 번호가 1.1. 꼴로 나온다).
- 개요 번호는 문서 앞에서부터 이어 센다. 손 번호가 그 순서와 다르면(건너뛴 번호 등) 그 문단은 뺀다.
- `--bind-styles`: 개요 번호에 더해 문서의 '개요 N' 스타일을 문단에 연결한다(스타일 목록·개요 보기에서
  같은 단계로 묶인다). rhwp 는 직접 서식이 있는 문단의 문단 모양을 유지한다(시험한 보도자료에서는 화면이 그대로였다).
  스타일이 없으면 B003.

## 판정

| 코드 | 뜻 | 차단 |
|---|---|---|
| B000 | 입력·계획 파일 문제, HWP 입력, 바꿀 문단 없음 | 예 |
| B001 | 개요 번호 정의가 공문서 순서와 다름 | 예 |
| B002 | 계획을 세운 뒤 입력 문서가 바뀜 | 예 |
| B003 | `--bind-styles` 인데 '개요 N' 스타일이 없음 | 예 |
| B200 | rhwp 편집 실패 (저장 후 다시 연 문서가 다르면 rhwp 가 그 문서를 보존 저장하지 못하는 경우) | 예 |
| B201 | 전후 `export-text`(공백 제외)가 다름 — 자동 번호가 손 번호를 재현하지 못함 | 예 |
| R103 | 원본보다 조판 이상 신호가 늘거나 쪽수가 바뀜 | 예 |
| B101 | 손 번호가 자동 순서와 다르거나 상위 단계가 없어 제외 | 아니오 |
| B102 | ㉮ 단계 — 개요 번호에 없어 제외 | 아니오 |
| B103 | 차례 항목(탭 뒤 쪽 번호) 제외 | 아니오 |
| B104 | 개체를 품은 문단 제외 | 아니오 |
| B105 | 바꾸면 조판이 흐트러지는 문단 제외 (한 문단씩 다시 적용해 찾음) | 아니오 |
| B106 | 앞 문단을 빼서 번호가 당겨지는 문단 제외 | 아니오 |
| B150 | 한글에서 줄바꿈·쪽 나눔이 바뀔 수 있음 (항상) | 아니오 |

한꺼번에 적용한 결과가 내용·조판 판정을 통과하지 못하면, 한 문단씩 다시 적용하며 B105·B106 문단만
빼고 나머지를 적용한다. 문서가 길면 이 단계가 수십 초 걸린다.

## 영수증

rhwp `run` 계획서는 이 편집(글자 지우기 + 문단 모양)을 담지 못해 작업 캡슐을 만들 수 없다.
보고서에 입력·계획·산출 SHA-256 과 실행한 rhwp 명령 목록을 남긴다.
