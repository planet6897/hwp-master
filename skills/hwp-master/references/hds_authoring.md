# HDS 작성법 (v1)

HDS v1의 제목·문단·표는 `rhwp scaffold` 명세 v1과 같다. 쪽 나눔·그림·글자 강조·각주·머리말·꼬리말은
빌드가 scaffold 결과에 `rhwp edit`으로 붙인다(`scripts/native.py`). 아래 밖의 필드나 블록은 오류(E002·E003)다.
수식·목록·글자 크기·셀 병합은 아직 없다. 미지원 표현을 그림이나 꼼수로 흉내 내지 않는다.

| 블록 | 필드 | 한글 문서에서 |
|---|---|---|
| `heading` | `level` 1~7, `text` | 개요 문단 (자동 번호, 굵게 12pt) |
| `paragraph` | `text`, `emphasis`·`footnotes` (선택) | 본문 문단 (10pt, 양쪽 정렬, 줄 간격 160%) |
| `table` | `rows` (문자열 2차원 배열), `cell_align` (선택) | 균등 열 폭 실선 표, 첫 행은 일반 행 |
| `page_break` | (없음) | 다음 블록을 새 쪽에서 시작 |
| `image` | `path`, `width_mm`·`caption`·`align` (선택) | 글자처럼 취급한 그림 한 줄(기본 가운데), 캡션은 그 아래 가운데 문단 |

문서 전체(Quick 은 HDS 최상위, Default 는 `spec_lock.json`)에 둘 수 있는 것:

| 필드 | 형식 | 한글 문서에서 |
|---|---|---|
| `header` | `{"text": "..."}` | 모든 쪽 머리말 한 줄 |
| `footer` | `{"text": "- {page} -"}` | 모든 쪽 꼬리말 한 줄. `{page}`는 쪽 번호 (한 번만) |

### 각주

```json
{"type": "paragraph", "text": "□ 처리 기간: 평균 3일 소요",
 "footnotes": [{"text": "2026년 1~6월 접수분 기준", "after": "평균 3일"}]}
```

- `after`를 주면 문단에서 그 글자가 **처음** 나오는 곳 바로 뒤에, 없으면 문단 끝에 각주 번호가 붙는다.
- 번호(`1)`, `2)` …)는 한글이 문서 순서대로 매긴다. 각주 본문은 한 문단이다.
- 제목·표 셀에는 각주를 달 수 없다. 출처는 각주로, 긴 보충 설명은 본문 문단으로 쓴다.

### 글자 강조

```json
{"type": "paragraph", "text": "□ 처리 기간: 평균 3일 소요, 전년 대비 40% 단축",
 "emphasis": [{"text": "평균 3일", "bold": true}, {"text": "40% 단축", "bold": true, "color": "#C00000"}]}
```

- `text`가 문단에서 **처음** 나오는 곳에 `bold`·`italic`·`underline`(true/false)·`color`(`#RRGGBB`)를 준다.
  적어도 하나는 있어야 한다. 같은 말이 두 번 나오면 강조할 쪽이 먼저 나오도록 `text`를 길게 잡는다.
- 핵심 수치·결론 한두 군데에만 쓴다. 문단 전체를 굵게 하지 않는다. 빨간색은 경고·변경 사항에만 쓴다.
- 제목은 이미 굵고, 표 셀에는 아직 강조를 줄 수 없다.

### 그림

```json
{"type": "image", "path": "sources/분기별_처리건수.png", "width_mm": 120,
 "caption": "<그림 1> 분기별 처리 건수"}
```

- `path`는 Default 프로젝트 폴더(Quick은 HDS 파일 폴더) 기준 상대 경로다. PNG·JPEG(BMP·TIFF도 됨)만 쓴다.
- `width_mm`를 빼면 원본 픽셀 크기(96dpi)로 넣고, 본문 폭(A4 기준 150mm)을 넘으면 본문 폭으로 줄인다.
  높이는 원본 비율을 따른다. 본문 폭보다 큰 `width_mm`는 오류(E112)다.
- 캡션 번호(`<그림 1>`)는 직접 쓴다(자동 캡션 번호는 아직 없다). 본문에서 "아래 그림"처럼 가리킨다.
- 자료에 없는 그림을 만들지 않는다. 차트는 자료의 수치로 그린 파일만 쓰고, 출처는 캡션이나 각주로 밝힌다.

### 쪽 나눔

- 장(1수준 제목)을 새 쪽에서 시작할 때처럼 꼭 필요한 곳에만 쓴다. 쪽을 채우려고 빈 문단을 넣지 않는다.
- 문서 맨 앞·맨 끝, 연달아 두 번은 오류(E105)다. 단위 파일의 끝에 두는 것은 괜찮다.

## 오류가 되는 것

| 코드 | 내용 |
|---|---|
| E101 | 제목에 번호를 직접 씀 (`"1. 추진 배경"`, `"가. 개요"`, `"Ⅲ. 일정"`) → 한글이 자동 번호를 붙여 이중 번호가 된다 |
| E102 | 제목 수준이 1~7 밖 |
| E103 | 빈 제목 |
| E104 | 빈 표 |
| E105 | 쪽 나눔이 문서 맨 앞·맨 끝이거나 연달아 있음 |
| E106 | `footnotes`가 빈 배열이거나 각주 `text`가 비었거나 `{text, after?}` 밖의 필드가 있음 |
| E107 | 각주 `after` 글자가 문단에 없음 |
| E108 | `header`/`footer`가 `{text}` 형식이 아니거나 `{page}`가 두 번 이상 |
| E109 | `emphasis`가 빈 배열이거나 서식 값이 없거나 형식이 틀림 (`color`는 `#RRGGBB`) |
| E110 | 강조 `text`가 문단에 없음 |
| E111 | `image` 필드가 틀림 (`path` 형식, `width_mm` 양수, 빈 `caption`, `align` 값) |
| E112 | `width_mm`가 본문 폭을 넘음 |
| E113 | 그림 파일이 없음 |
| E005 | `cell_align`이 `justify`/`left`/`center`/`right`(또는 열별 목록)가 아님 |

## 개조식 작성 (v1 임시 규약)

v1에는 목록 블록이 없으므로 기호를 문단 텍스트 앞에 직접 쓴다.

- 1단계 `□`, 2단계 앞에 공백 두 칸 + `○`, 3단계 공백 네 칸 + `-`
- 문장은 명사형으로 끝낸다 ("~함", "~임", "~필요"). 마침표를 찍지 않는다.
- 수치는 자료에 있는 값만 쓰고 단위를 붙인다.
- 4단계는 공백 여섯 칸 + `ㆍ`. 단계를 건너뛰지 않는다(`□` 다음 바로 `-` 금지, C011).
- 기호 뒤에는 한 칸만 띄운다(C101). 서술형 종결("~합니다.")은 C111 경고다.

## 공문서 항목 (`convention: gongmun`)

- 본문 항목은 `1.` → `가.` → `1)` → `가)` → `(1)` → `(가)` → `①` → `㉮` 순서로 내려간다.
  하위 항목은 상위 항목보다 두 칸 들여 쓴다.
- 단계를 건너뛰지 않고(C001), 같은 단계는 1·2·3, 가·나·다 순서로 이어 간다(C002).
  상위 항목이 바뀌거나 제목이 나오면 하위 번호는 다시 1 또는 가부터 시작한다.
- 기호 뒤에는 한 칸만 띄운다(C101). 날짜(`2027. 3. 1.`)는 항목으로 보지 않는다.

## 표

- 머리행은 첫 행에 둔다. 숫자 열은 `right`, 구분 열은 `center`, 설명 열은 `left`.
- 열 폭은 균등하다(v1). 긴 설명이 필요한 표는 열 수를 줄이거나 표 아래 문단으로 설명한다.
